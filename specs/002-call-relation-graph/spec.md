# Feature Specification: 调用关系全量扫描页面

**Feature Branch**: `002-call-relation-graph`  
**Created**: 2026-03-25  
**Status**: Draft  
**Input**: 增加调用关系图谱 菜单、页面、以及该功能涉及到的数据库表

## 背景与现状

系统已具备完整的调用关系扫描引擎（全量扫描 + Webhook 驱动的增量扫描），后端全量扫描 API 也已实现（`POST /api/relation/scan`）。`call_relation` 数据库表建表脚本和菜单 SQL 均已就绪，唯独缺少面向用户的前端操作入口，导致全量扫描只能通过接口工具调用。

本功能的核心目标是**提供一个操作页面**，让用户能够一键触发全量调用关系扫描并实时查看扫描执行状态，同时确认菜单和数据库表的落地。

## User Scenarios & Testing

### User Story 1 — 触发全量扫描并查看执行状态 (Priority: P1)

运维/架构人员希望在浏览器中点击一个按钮，触发全量调用关系扫描（遍历全部 Java 代码、重建 `call_relation` 表），并能在扫描执行期间持续看到当前状态，扫描完成后看到结果摘要。

**Why this priority**: 这是本功能唯一的用户故事，是全部功能的核心。

**Independent Test**: 进入页面，点击"触发全量扫描"按钮，按钮禁用并出现状态区域，等待扫描完成后页面显示写入边数和耗时，即可完整验证本功能。

**Acceptance Scenarios**:

1. **Given** 用户进入调用关系扫描页面，**When** 页面加载完成，**Then** 显示"触发全量扫描"按钮，按钮可点击，状态区域显示"就绪"
2. **Given** 用户点击"触发全量扫描"按钮，**When** 后端开始处理，**Then** 按钮立即变为禁用状态并显示"扫描中…"，状态区域出现当前执行阶段描述（如"正在扫描 Java 文件…"）
3. **Given** 扫描正在执行，**When** 用户查看页面，**Then** 状态区域持续更新/轮询当前执行进度，不出现空白或卡顿
4. **Given** 扫描执行完成，**When** 接口返回成功，**Then** 按钮恢复可点击，状态区域展示结果摘要："扫描成功，写入 X 条边，耗时 Ys"
5. **Given** 扫描执行失败（如代码目录不存在），**When** 接口返回错误，**Then** 按钮恢复可点击，状态区域以红色显示错误原因，不出现空白或崩溃

---

### Edge Cases

- 扫描过程中用户刷新页面，刷新后按钮应恢复可点击状态（不锁死），状态区域重置为"就绪"
- 连续快速点击"触发全量扫描"按钮，按钮禁用期间的重复点击应被忽略，不触发多次扫描
- 后端扫描超时（超过 30 分钟），页面应显示超时提示而非永久等待

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供 `call-relation.html` 页面，通过菜单导航可达
- **FR-002**: 页面 MUST 包含"触发全量扫描"按钮，点击后调用 `POST /api/relation/scan` 接口
- **FR-003**: 按钮点击后 MUST 立即禁用，并在状态区域显示"扫描中…"，防止重复提交
- **FR-004**: 扫描执行期间，状态区域 MUST 持续反馈当前执行阶段（通过轮询或状态接口获取），不得长时间无响应
- **FR-005**: 扫描完成后，页面 MUST 展示结果摘要，包含：写入调用关系边总数、本次扫描耗时
- **FR-006**: 扫描失败时，页面 MUST 以醒目方式（红色提示）展示错误原因，按钮恢复可点击
- **FR-007**: 系统 MUST 执行 `add_call_relation_menu.sql`，将"调用关系图谱"菜单项写入 `sys_menu` 表，导航栏可见
- **FR-008**: 系统 MUST 执行 `create_call_relation_table.sql`，确保 `call_relation` 表已建立

### Key Entities

- **调用关系边（call_relation）**：全量扫描的输出目标，每次全量扫描会清空并重建该表。表已有建表脚本，无需改动
- **菜单项（sys_menu）**：导航栏中的菜单记录，关联页面 URL `/call-relation.html`，通过 `add_call_relation_menu.sql` 写入

---

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从点击菜单到看到扫描页面，加载时间不超过 2 秒
- **SC-002**: 点击"触发全量扫描"按钮后，状态区域在 1 秒内出现"扫描中…"反馈
- **SC-003**: 扫描完成后，结果摘要中写入边数与数据库 `call_relation` 表实际行数一致
- **SC-004**: 任何扫描失败场景下，页面均能显示错误提示，不出现空白页或未处理异常

---

## Assumptions

- 前端使用 Vue 3 + axios（已内嵌 static 目录），无需引入额外依赖
- 页面风格与现有页面（如 `flow-tree-query.html`）保持一致
- 后端 `POST /api/relation/scan` 接口已完整实现，本功能不需要修改任何 Java 代码
- 扫描状态反馈通过前端轮询 `GET /api/relation/summary` 接口（已实现）实现，无需新增后端接口
- 菜单 SQL 和建表 SQL 已存在于项目中，本功能确认其已执行即可，无需重写
- 图谱可视化、违规列表、依赖链查询、影响面查询等功能**明确不在本期范围内**
- 移动端适配不在本期范围内，以桌面宽屏（≥1280px）为主要场景
